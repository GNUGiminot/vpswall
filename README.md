# VPSWall — консольное меню для UFW

Локальное приложение на Go для управления firewall одного VPS через SSH.
Запускается одной командой, меню на русском, выбор пунктов цифрами и Enter.
Работает с существующими правилами UFW. Не заменяет UFW и не управляет firewall в панели хостинга.

## Возможности

- Состояние, политика, нумерованные и сохранённые правила; индикатор поддержки IPv6.
- Добавление allow / deny / limit: TCP/UDP, порт или диапазон, IP/подсеть, комментарий.
- Добавление в начало или конец списка; замена выбранной строки на той же позиции; удаление строки.
- Шаблон HTTP/HTTPS, политика входящих, включение/выключение UFW.
- Слушающие порты с процессами, последние записи UFW в журнале ядра.
- Полные копии `/etc/ufw` и `/etc/default/ufw`, история изменений, восстановление копии.
- Каждое изменение применяется временно с автоматическим откатом через 120 секунд.
- После обычной перезагрузки неподтверждённое изменение восстанавливается службой systemd.

## Требования

Linux с systemd и UFW, архитектура amd64 или arm64, права root через sudo.
Целевое окружение: Ubuntu 22.04/24.04 и Debian 12/13. На этих дистрибутивах
работа ещё не подтверждена живым тестом: сборка выполнялась на Windows.
Зависимости runtime: `/usr/sbin/ufw`, `/usr/bin/systemctl`, `/usr/bin/systemd-run`,
`/usr/bin/cp`; для диагностических пунктов также `ss` и `journalctl`.
Go на VPS не требуется. Система без systemd не поддерживается.

## Установка

Скачайте готовый архив из [выпуска v0.1.0](https://github.com/GNUGiminot/vpswall/releases/tag/v0.1.0).
На VPS это можно сделать следующими командами (Go не требуется):

```sh
sudo apt update
sudo apt install ufw unzip curl
curl -fL https://github.com/GNUGiminot/vpswall/releases/download/v0.1.0/vpswall-0.1.0.zip -o vpswall-0.1.0.zip
```

Затем распакуйте и установите приложение:

```sh
unzip vpswall-0.1.0.zip -d vpswall
cd vpswall
sudo sh ./install.sh
sudo --preserve-env=SSH_CONNECTION vpswall
```

Если UFW уже установлен, команды apt можно пропустить. Установка приложения
не включает UFW и не меняет его правила. Устанавливаются `/usr/local/bin/vpswall`
и служба `vpswall-recover.service`; состояние и копии хранятся в `/var/lib/vpswall`
с доступом только root. Скрипт выбирает нужную архитектуру автоматически.
Для обновления повторите установку, завершив предыдущую транзакцию.

## Безопасное изменение

1. Проверьте состояние и реальный порт SSH. При необходимости сначала добавьте
   разрешение на этот порт с вашего IP или подсети, включая нужное семейство IPv6.
2. Выберите действие. Программа покажет команду/изменение и попросит ввести `да`.
3. Сначала создаётся копия и запускается независимый таймер systemd. Если таймер
   не запускается, правила не изменяются. Ошибка применения вызывает немедленный откат.
4. После применения откройте **новое** SSH-подключение. В нём выполните команду
   с выданным кодом, например:

   ```sh
   sudo --preserve-env=SSH_CONNECTION vpswall confirm ВЫДАННЫЙ_КОД
   ```

5. Без подтверждения происходит откат. Выход из меню и разрыв SSH таймер не отменяют.
   Второе изменение заблокировано, пока первое не подтверждено или не отменено.

На подтверждение отводятся 120 секунд с начала транзакции, включая время выполнения
UFW. Код можно посмотреть через `sudo vpswall status`. Изменения уже сохраняются
самим UFW; подтверждение отменяет откат, отдельное «сохранение» не требуется.

Новое подключение проверяется сравнением `SSH_CONNECTION`: сохраняйте эту переменную
при запуске меню через указанную команду sudo. В локальной консоли, если переменной
нет, код можно подтвердить в той же консоли. Не запускайте удалённое меню с удалённой
из окружения переменной: программа тогда не сможет отличить SSH от локальной консоли.
При включении UFW текущая SSH-сессия тоже может оборваться — повторно подключитесь
и подтвердите, если доступ работает; иначе дождитесь восстановления.

Это защита от ошибочного правила, а не гарантия доступности при сбое диска, systemd
или самого сервера. При ошибке восстановления pending-состояние сохраняется,
служба повторяет попытку. Журнал: `journalctl -u vpswall-rollback.service` и
`journalctl -u vpswall-recover.service`. Перед первым живым испытанием нужен доступ
к консоли VPS в панели хостинга.

## Команды

```sh
sudo --preserve-env=SSH_CONNECTION vpswall   # меню
sudo vpswall status                        # состояние и правила
sudo vpswall rollback                      # немедленный откат текущей транзакции
vpswall --version
vpswall --help
```

## Особенности правил

- IPv4 и IPv6 отображаются отдельными строками UFW. Удаление по номеру удаляет одну
  строку. Для замены необходимо явно указать семейство источника: `0.0.0.0/0`
  для всех IPv4, `::/0` для всех IPv6, либо конкретный IP/подсеть того же семейства.
  Замена создаёт обычное входящее правило TCP/UDP; интерфейсные, исходящие и
  маршрутизирующие правила через этот редактор не заменяйте.
- `any` при добавлении создаёт правила для семейств, включённых в UFW. Приложение
  показывает `IPV6=...`, но само настройку IPv6 не изменяет.
- Редактирование/удаление по номеру доступны при включённом UFW. При выключенном
  UFW можно добавлять и просматривать сохранённые правила; они не фильтруют трафик.
- Первое подходящее правило имеет приоритет. Запрет в конце после широкого
  разрешения может не работать; используйте добавление в начало.
- `limit` доступен для TCP. Это ограничение частоты соединений, а не Fail2ban.
- Не меняйте UFW другими программами во время ожидающего подтверждения: откат
  восстанавливает снимок всей конфигурации UFW, включая сторонние правки после снимка.
- Docker управляет своими правилами, и опубликованные порты могут обходить UFW.
  При обнаружении сокета Docker программа предупреждает об этом. Docker-правила,
  Fail2ban и внешние цепочки программа непосредственно не редактирует.
- Доступность извне определяется также firewall хостинга, маршрутизацией и сервисом.
  Успешное SSH-подключение не проверяет доступность сайта или базы — проверяйте их отдельно.
- Управление несколькими VPS сейчас выполняется запуском программы на каждом из них.
  Центрального списка серверов и хранения SSH-ключей в этой версии нет.

## Сборка и проверки

На Windows: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1`.
Скрипт проверяет код и тесты, собирает Linux amd64/arm64 без сторонних Go-модулей,
затем создаёт архив установки и SHA-256 файлов.

На Linux с Go 1.22+:

```sh
go test ./...
go vet ./...
mkdir -p dist
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o dist/vpswall-linux-amd64 .
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -o dist/vpswall-linux-arm64 .
```

Автотесты используют временные каталоги и подменённые команды: проверяют валидацию,
безопасную передачу аргументов, отказ таймера, восстановление файлов и исходного
состояния UFW, частичный сбой, блокировку параллельных изменений, подтверждение из
нового SSH и истечение срока. Они не изменяют firewall машины, где запускаются.

### Ручная проверка на тестовом VPS

1. Установить, посмотреть правила и копию. Проверить, что установка ничего не изменила.
2. Добавить тестовое разрешение, подтвердить из нового SSH, проверить правило.
3. Добавить другое правило без подтверждения, выйти из меню, через 130 секунд
   проверить, что восстановились правила и исходное состояние включения UFW.
4. Повторить без подтверждения и перезагрузить: проверить восстановление и журнал
   `vpswall-recover.service`.
5. Проверить замену/удаление IPv4 и IPv6 строк и доступность нужных сервисов извне.

## Удаление приложения

Сначала подтвердите изменение или выполните `sudo vpswall rollback`.
Убедитесь, что `/var/lib/vpswall/pending.json` отсутствует. Затем:

```sh
sudo systemctl disable --now vpswall-recover.service
sudo rm /etc/systemd/system/vpswall-recover.service
sudo systemctl daemon-reload
sudo rm /usr/local/bin/vpswall
```

Копии и история остаются в `/var/lib/vpswall`, действующие правила UFW сохраняются.

Справка: [UFW](https://manpages.debian.org/unstable/ufw/ufw.8.en.html),
[systemd-run](https://manpages.ubuntu.com/manpages/noble/man1/systemd-run.1.html),
[Docker и firewall](https://docs.docker.com/engine/network/packet-filtering-firewalls/).
